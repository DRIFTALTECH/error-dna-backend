How SAP Notes are scraped, summarized, embedded, and stored

A pending URL is claimed by the background scheduler. OpenClaw drives headless Chrome through SAP login, the page text is cleaned, DeepSeek rewrites it into a structured knowledge-base entry, that row is inserted into PostgreSQL, and Amazon Titan V2 then stores a 1024-dimension vector of a canonical text blob.

One sentence. Scheduler → scrape me.sap.com → LLM JSON summary → summaries table → Titan embed of title + family + issue + summary + tags + gotchas → summary_embeddings.

1. How a note enters the queue

Someone adds a SAP Note URL from the UI (or an Excel upload). That is a plain INSERT into urls: source_id (note number), source_url, title, component, dates. Status starts as pending. Nothing is scraped yet.

On API startup, main.py lifespan calls services.scheduler.start(). That loop wakes every 30 seconds (and respects a random delay between scrapes, plus a pause if community ingest is using Chrome).

2. Scheduler claims one URL

Each run of one_scrape() does this, in order:

  1. Load the active SAP credential from credentials (is_active=1). Password is Fernet-decrypted.
  2. Atomic claim — one SQL statement sets the oldest pending row to scraping and returns it. Two API processes cannot grab the same URL.
  3. If the queue is empty, it returns.
  4. Skip if already in the KB. If summaries already has is_latest=1 for that source_id with source_version ≥ 1, the URL is marked skipped. No scrape, no LLM, no embedding.
UPDATE urls SET status='scraping'
 WHERE id = (SELECT id FROM urls WHERE status='pending' ORDER BY id ASC LIMIT 1)
 RETURNING *

3. Browser scrape (OpenClaw)

scrape_note(url, username, password) runs in a worker thread (it is synchronous subprocess I/O). A process-wide lock ensures notes scrape, community ingest, and credential test-login never interleave Chrome commands.

navigate Open source_url via openclaw browser navigate. If the active SAP account changed since last scrape, cookies are cleared first.
probe A DOM probe returns URL, text length, password field, S-user tiles, buttons. classify() maps that to a state.
state machine Up to 18 steps: landing → login_user → login_pass → account_select → keep_signed → consent → target. MFA cannot be automated — scrape fails with mfa_required.
extract Target page = text length > 200 and contains “symptom” / “resolution”. Inner text of [role=main] is pulled.
parse Lines are split into TITLE + SYMPTOM + ENVIRONMENT + RESOLUTION + KEYWORDS. Chrome UI chrome is dropped. Result: clean_text.
attachments Best-effort: click Attachments tab, download files, extract text (XSD/XML/PDF/…), append to clean_text for the LLM. Bytes are kept so the scheduler can persist them.
If scrape fails, the URL is set to failed, a row is written to scrape_log with the step trace, and the job stops. No LLM. No embedding.

4. Attachments are saved before the LLM

Each attachment’s bytes go through image_store.save(..., kind="doc") — S3 if S3_BUCKET is set, otherwise local data/images/. A manifest [{name, key, ext}] is kept. If the LLM later fails, those blobs are deleted so they do not orphan.

5. Passing the note to the LLM

summarize(clean_text) in services/summarizer.py POSTs to a DeepSeek-compatible chat-completions endpoint (LLM_API_URL, default https://api.deepseek.com/v1/chat/completions, model deepseek-chat).

PieceWhat is sent
System promptSenior technical writer. Ignore page chrome. Never say “SAP”. Classify into one family code from the live catalog (error_families seeded from data/error_families.csv).
User promptSummarize this technical article: plus the first 15,000 characters of clean_text (attachments already appended).
API knobstemperature=0.3, max_tokens=4000, response_format=json_object, 60s timeout.

Expected JSON keys:

{
  "title": "...",
  "family": "OAUTH_TOKEN_REQUEST_FAILED",   // catalog CODE, not display name
  "area":  "same as family",
  "type":  "Problem" | "How To" | "FAQ" | "Configuration",
  "issue": "2–3 sentences of what goes wrong",
  "summary": "root cause + technical context",
  "steps":  [{ "title": "...", "details": ["..."] }],
  "gotchas": ["..."],
  "tags": ["..."],
  "environment": ["Cloud Integration", "BTP"]
}

Family is not trusted blindly

  1. If the LLM’s family is a known catalog code, keep it.
  2. Else try mapping it as a display name via code_from_family_field.
  3. Else regex-classify issue + summary with classify_text (patterns on error_families, lowest match_priority wins).
  4. If still unknown → UNCLASSIFIED_ERROR.

Arrays (steps, gotchas, tags, environment) are JSON-stringified before they hit PostgreSQL, because those columns are TEXT.

6. Saving the summary

One INSERT into summaries, then the URL is marked completed:

INSERT INTO summaries (
  source_id, url_id, title, family, area, type, issue, summary,
  steps, gotchas, tags, source_version, source_date, source_url,
  component, environment, attachments, is_latest, verification_status,
  created_at, updated_at
) VALUES (..., 1, 'current', now_ist, now_ist)
RETURNING id

UPDATE urls SET status='completed', scraped_at=? WHERE id=?

attachments stores the S3/local key manifest, not the file bytes. Timestamps are IST text, not timestamptz.

A success row is also written to scrape_log with the full step trace (navigate, login, extract, summarize, store, embed).

7. Finding and saving the embedding

Immediately after the summary INSERT, the scheduler calls embed_summary_safe("notes", summary_id, source_id, row). This is best-effort: if Bedrock fails, the scrape is still a success. The note exists without a vector until a backfill job runs.

Canonical blob (this is what gets embedded — not the raw SAP page)

TITLE: {title}

FAMILY: {family}

ISSUE: {issue}

SUMMARY: {summary}

TAGS: {tags}

GOTCHAS: {gotchas}

Defined in services/embeddings.py:build_blob. Images, attachment bodies, raw page text, steps, and source URLs are not in the vector. Changing this format would invalidate stored hashes and force re-embedding.

Exact embed steps — do not skip any

  1. Build the blob string from the six fields above.
  2. SHA-256 hex digest of the blob → content_hash.
  3. SELECT existing row from summary_embeddings where source='notes' AND summary_id=?.
  4. If a row exists and the hash matches → skipped. Titan is not called. This is how re-scrapes of unchanged text stay cheap.
  5. Otherwise call Amazon Titan Text Embeddings V2 via Bedrock (amazon.titan-embed-text-v2:0, region from EMBED_REGION). boto3 is synchronous, so it runs in asyncio.to_thread.
  6. Request body: {"inputText": blob, "dimensions": 1024, "normalize": true}.
  7. Response must be exactly 1024 floats. They are already L2-normalized.
  8. Convert the list to a pgvector text literal [0.12, -0.03, ...] (asyncpg has no vector codec).
  9. UPSERT:
INSERT INTO summary_embeddings
  (source, summary_id, source_id, content_hash, embedding, model, created_at, updated_at)
VALUES (?, ?, ?, ?, ?::vector, ?, ?, ?)
ON CONFLICT (source, summary_id) DO UPDATE SET
  source_id, content_hash, embedding, model, updated_at = EXCLUDED...
ColumnMeaning
source'notes' for SAP Notes. Community uses 'community' in the same table.
summary_idPrimary key of the summaries row just inserted.
source_idSAP Note number (e.g. 3780883).
content_hashSHA-256 of the blob. Skip-if-unchanged key.
embeddingvector(1024) — pgvector. Cosine distance <=> later.
modelamazon.titan-embed-text-v2:0
After this, the note is searchable. Diagnose and MCP hybrid_search both query summary_embeddings with the same Titan model so query vectors and stored vectors live in one space.

8. Parallel path: SAP Community (same embed shape)

Community is not on the scheduler. A UI action drains community_urls one-by-one (services/community_ingest.py). Differences that matter:

  • No SAP login. OpenClaw waits out Cloudflare, captures up to 3 content images.
  • LLM is called with allow_skip=True. Blogs/announcements return {"is_solution": false} and are not stored.
  • Row goes to community_summaries, not summaries.
  • Embedding still uses embed_summary_safe("community", ...) and the same blob format in summary_embeddings.

9. Backfill

If a scrape succeeded but Bedrock was down, the note has no vector. services/embed_backfill.py finds latest summaries with no matching summary_embeddings row and calls the same upsert_embedding.

Written on success
  • urls.status = completed
  • summaries row
  • summary_embeddings row (if Titan worked)
  • scrape_log success + trace
  • Attachment blobs in S3 / local disk
Not embedded
  • Raw SAP HTML / innerText
  • Step-by-step JSON (except what leaked into summary text)
  • Attachment file bodies (text is in the LLM prompt, not the vector)
  • Note number / URL / dates
